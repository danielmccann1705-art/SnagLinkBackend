# Private selected-source staging — storage contract

Base backend `90748aa3aaa58a8b84f191ea4e9b240c73c9a4c3`. Additive overlay only; no route or application migration registration yet. Its migration and 13 unique cases have actual isolated PostgreSQL passing evidence across the final 12-case run plus one corrected focused fixture test (see integration README); deployment and complete import remain unverified. This is server storage of a selected export, not a published/imported project.

## Binding and state

`staged_legacy_imports.id` is the caller-retained session UUID. It binds current authenticated actor UUID + current `authVersion`, actual Team/workspace UUID and kind, canonical **API** origin and environment, non-authenticating installation UUID, distinct create-stage operation UUID, selected source project UUID, archive source fingerprint, exact export SHA-256 and byte count. The fixed acknowledgement wording/version/accepted condition is in `StagedLegacyImportCommand.Acknowledgement`. The retained wording authorises private preparation of this exact source/destination; it does not assert verified historic ownership, authorship or acceptance. The server records its present receipt time, never a client-supplied historical consent date.

The service command is an internal value, not a public HTTP DTO: `expectedAuthVersion` is supplied from the authenticated server context (current public user/session responses do not expose it). A future route must add strict closed-key wire decoding and independent body/rate limits; it must never accept an account/version pair as authentication.

Current active Owner/Admin authority is checked under `WorkspaceAccessService.lock`, without ProjectAccessService/adoption/workspace discovery. A `users FOR SHARE` lock prevents an auth-version/lifecycle change during the transaction. The current company membership role/state/revision and workspace owner/revision are part of an immutable authority fingerprint. Removal/rejoin, role/owner change, auth-version change or a changed API/device/source fails closed. The caller must separately authenticate a currently valid native token/browser session and enforce browser CSRF: an account UUID or device UUID is never authentication.

States: `staged_incomplete` revision 1 → `aborted` revision 2. No ready/committed/executable state. A trigger only permits that exact transition and forbids binding mutation. An abort retains source records, mapping IDs and declarations; create retry returns current aborted state, never reactivates it. Read is actor-private compact metadata. No second manager, even an Owner, can resume someone else's staging source.

Create has its own stable operation ID, separate from the diagnostic preview operation. Global `mutation_receipts` stores a small session pointer and the create request hash. Operation reuse for a changed descriptor/destination/device/body conflicts. A unique `(actor_id, environment, api_origin, source_fingerprint, source_project_id)` rejects a second preparation of the same bound source in another workspace, including after abort. Later deliberate reauthorisation/reconciliation is not implemented; never work around a conflict by silently changing the source fingerprint.

## Source tables and future upload linkage

| Table | Key / stable identity | Retained value |
| --- | --- | --- |
| `staged_legacy_import_sources` | `session_id` | Exact descriptor BYTEA, 1…8 MiB; original bytes SHA verified before storage and rechecked on replay/load. |
| `staged_legacy_import_records` | `(session_id, kind, source_id)`; stable `mapping_id` UUID | Entire typed record JSON with default native reference-date/fractional dates, projection digest, `proposed_target_id = source_id`, fixed `mapping_state = unreserved_source_id`. No canonical reservation or foreign-ID ownership claim. |
| `staged_legacy_import_edges` | `(session_id, position)` | Typed source kind/UUID/field and target kind/UUID with `target_present`; missing edges remain declared. |
| `staged_legacy_import_files` | `(session_id, archive_path)`; unique `(session_id,declaration_id)` | Stable declaration UUID, source-private relative archive handle, declared size/SHA, fixed `verification_state = unverified_declaration`. |
| `staged_legacy_import_file_uses` | `(session_id,kind,source_id,role,position)`; stable `use_id` UUID | Every required/optional file reference including missing/not-recorded/unsafe declarations. Exact typed FileReference JSON retains source hash/size/path/drawing-fallback facts. |
| `staged_legacy_import_actions` | `(session_id,revision)` | Current actor/device/operation and current timestamp for `source_staged` or `preparation_aborted`. Never substitutes importer as a historical author. |

All six source/action tables reject UPDATE/DELETE. Ordinary sources/records are never read through canonical lists/snapshots, source child UUIDs are not globally reserved, and no workspace change sequence or workflow notification is written. Same-kind source IDs are preserved; folders/directory identities shared across several future project imports will need deliberate source-level reconciliation before publication, not new random target IDs on retry.

**Actual file transport should add a separate measured-byte receipt table** referencing `(session_id,declaration_id)`. Never update the immutable source declaration to mean verification. `archive_path` is only a private lookup handle; never use it as an R2 key, URL or log label. Derive destination keys from server-controlled session/declaration IDs. Preserve distinct role/use edges when several roles reference one declared file. Cross-session hash matches do not authorise byte reuse. Source file roles include opaque historical attachments and deleted-photo retention; store their measured bytes without claiming successful image decode. Image/PDF/raster validation and derived rendition receipts are additional facts, never replacement originals or canonical accepted evidence.

`StagedLegacyImportService.withActiveSession(scope:actor:binding:on:body:)` rechecks account/workspace/fingerprint/device/source/API and state inside its own transaction, then invokes the callback with current compact receipt and transaction DB. Use it before allocation and **again after object IO** before recording a measured receipt. Do not hold a DB lease over network IO or reuse a returned receipt as future permission. The upload layer still needs operation-idempotency, expected session revision, bounded stream/hash/length verification, conditional immutable object writes, incomplete-object cleanup, repeated authority checks, and source-specific file-role resolution. An abort or revoked membership during streaming must prevent readiness publication.

## Bounds, privacy and remaining lifecycle gates

The existing full decoder/graph validator remains authoritative: exact native schema, 8 MiB descriptor, 2 GiB total declared bytes, strict typed file paths, all source findings, and conservative ≤1,000 journal / ≤10,000 future snapshot projection budget. Current managed workspace contractor+trade counts are queried under the workspace lock; the client supplies no directory count. A create is rejected whole before source publication when the budget does not fit. Staging additionally caps retained sessions at 32 and raw descriptor bytes at 64 MiB per actor (operational guard, not subscription pricing). Exact descriptors, projection duplication and database overhead still need operational capacity measurement.

No raw source HTTP response exists. `loadVerifiedGraph` is an internal typed consumer with current authority checks and denies aborted preparations. These private values contain contacts, names, paths, GPS and unverified historical authors; never log them or include them in Contractor links, normal mutation receipts, analytics or exception text. Descriptor and source-record projections retain excluded-category counts and all finding/limitation markers. Excluded profile credentials, PINs/tokens and executable pending requests remain outside the native export.

Fluent's pinned `Database+Concurrency.transaction` bridges the transaction into `eventLoop.makeFutureWithTask`, and NIO's pinned `EventLoopFuture.get` explicitly does not respect structured cancellation. The staging service therefore creates its own synchronised cancellation fence outside that bridge. It checks every retained source row and again after the present action and global retry receipt, before returning to Fluent's COMMIT boundary. Two actual PostgreSQL tests pause inside action and receipt writes, cancel the outer task, then prove zero session/source/mapping/action/receipt rows and successful same-operation restart. A cancellation arriving after the last application check may race COMMIT: the caller must treat that as an uncertain outcome and retry the same operation, not invent an undo. This is transaction/restart evidence, not a physical power-loss or provider durability guarantee.

Abort is **not erasure**. This storage-only slice has no account-deletion or source-redaction service, no automatic cleanup schedule and no public historical-source output. Before accepting real source uploads through routes, implement the explicit retention/withdrawal policy and account/workspace deletion lifecycle. Before exposing any history or raw-derived view, implement current redaction overlays that suppress both record projections and whole-source replay/download; unverified source author UUIDs cannot grant redaction authority to unrelated accounts. Keep local originals/recovery exports unchanged. The immutable SQL guards deliberately require a reviewed lifecycle migration rather than accidental DELETE; they must not become a reason to ignore a legitimate erasure workflow.
