## Ranked confirmed blockers

### 1. P1 — Native data and pending operations are not isolated by account

[SnaglistApp.swift:43](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/App/SnaglistApp.swift:43) partitions staging from production, but creates one persistent store per environment. [SLPendingChange.swift:5](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Models/SLPendingChange.swift:5) has no account owner; `SyncManager.processPendingChanges` [fetches the entire queue](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/SyncManager.swift:138), then uses the current API client. `AuthManager.signOut` [clears credentials, not models/media](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/AuthManager.swift:150). [PhotoStorageService.swift:59](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/PhotoStorageService.swift:59) stores photos by project UUID without account partitioning; floor plans and widget exports also need coordinated ownership.

Trigger: A leaves offline edits, signs out, and B signs in. Pending creates may be sent with B's credentials; prior local content remains in the shared store. New `sessionRevision` guards protect adoption of some authentication results, not ordinary sync/cache work.

**Next:** partition models, outbox, files and widget exports by stable account/workspace; capture account/revision across every awaited sync operation; quarantine ambiguous legacy ownership. Preserve anonymous drafts through an explicit claim policy. **Accept with:** two-account offline/switch/relaunch/delayed-response tests proving no display, upload or deletion across owners, including revoked company access and queued approvals/deletions. The parent is handling the native sync prerequisites.

### 2. P1 — Account deletion and Apple revocation still do not exist

[APIClient.deleteAccount](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/APIClient.swift:364) sends DELETE users/me; [UserProfileController.boot](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Controllers/UserProfileController.swift:9) registers only GET/PATCH and usage. No account-deletion handler or Apple authorization-code exchange/revocation was found in current backend Sources. [SettingsView.deleteAccount](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Views/Settings/SettingsView.swift:641) correctly retains recovery state on failure, but hypothetical success still clears only caches/photos before local sign-out.

**Next:** implement durable, idempotent deletion with honest pending/completed responses. Use the existing account lifecycle/auth-version controls to stop writes and sessions immediately. Inventory legacy content plus new `user_identities`, browser sessions, identity/Google challenges, memberships/grants/invites, private media, register snapshots/change payloads, reports and provider data. Apply explicit shared-company ownership/retention rules; preserve cleanup receipts until external deletion completes. Add secure Apple exchange/revocation and reauthentication for old users without revocable tokens. Google SDK sign-out and RevenueCat logout do not remove the backend identity or customer data.

**Accept with:** wrong-owner and repeated deletion, restart/provider-failure recovery, invalidated native/browser/link access, preserved unrelated company content, complete local/media cleanup, and a controlled Apple revocation round trip. Apple requires in-app initiation, associated-data removal and Sign in with Apple revocation; delayed processing must be clear. [Apple guidance, rechecked today](https://developer.apple.com/support/offering-account-deletion-in-your-app/).

### 3. P1 — Purchases have no complete account-bound server refresh

[SubscriptionManager.purchase/restorePurchases](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/SubscriptionManager.swift:53) update only local `hasProEntitlement`. No native call was found that requests authoritative refresh after purchase, restore or login. [SubscriptionVerificationService.currentTier:77](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Services/SubscriptionVerificationService.swift:77) immediately returns free for stored-free users; explicit refresh currently occurs through a [profile tier hint](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Controllers/UserProfileController.swift:53). A genuine new purchase can leave server allowance free.

Separately, [refreshTier:101](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/SubscriptionManager.swift:101) grants local Pro from a global Boolean even while signed out. `signOut` does not reset it; RevenueCat logout/login and customer-info callbacks are asynchronous and lack account-generation checks. A's cached or late purchase result can be applied during B's session. This is a local entitlement defect, **not** a current server self-upgrade vulnerability: backend verification remains authoritative and bounded to five minutes.

**Next:** serialize provider identity transitions, clear/account-bind local entitlement state and discard stale callbacks; refresh the server after login/purchase/restore/customer changes. Keep client hints non-authoritative. **Accept with:** sandbox purchase/refund/expiry/restore and A→B switching, including delayed callbacks and provider outage. Legacy RevenueCat UUID aliases/transfers remain unverified; prove the rightful account retains purchases after upgrade/reinstall without transferring entitlement by email or an untrusted client ID.

### 4. P1 — Private media improves access control but does not complete retention/deletion

V2 now records owner/grant, intent, workspace/project/snag and expiry in [PrivateMediaService.allocate](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Services/PrivateMediaService.swift:12). This supersedes the earlier blanket “no media ownership” finding. It uses a separate private bucket, strict keys, metadata-free rendered JPEGs and permission checks before and after download.

Remaining concrete gaps: [StorageService:184](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Services/StorageService.swift:184) implements private upload/download but no private delete. [CleanupService.runCleanup](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Services/CleanupService.swift:14) does not purge expired/unattached private objects. The 24-hour expiry prevents access but does not remove bytes. Legacy [UploadController:93](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Controllers/UploadController.swift:93), still called by the Clip, writes public URL-based media without an upload ledger; abandoned uploads remain unassociated. Private original images intentionally retain their original metadata.

**Next:** implement reference-aware private object cleanup with durable retries and orphan expiry; migrate/retire legacy public uploads deliberately. Include original metadata and retained shared evidence in policy/deletion scope. **Accept with:** removed/revoked recipient cannot fetch media, direct private-bucket access fails, expired or abandoned objects are removed, shared references survive correctly, and external URLs cannot authorize deletion. Bucket public-access settings and Linux image-processing behavior remain unverified in this review.

### 5. P1 deployment prerequisite — Current container adapter omits new feature configuration

[containerEnvironment:44](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Infrastructure/cloudflare/src/config.mjs:44), used as [Container.envVars](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Infrastructure/cloudflare/src/index.ts:14), forwards only legacy staging configuration. It omits `PORTAL_ORIGIN`, `PLATFORM_ENVIRONMENT`, Google environment/client IDs, `R2_PRIVATE_BUCKET_NAME` and `LINK_GRANT_TOKEN_KEY`. The respective new services fail closed without them. Setting Worker variables alone cannot enable those features through this map. The adapter also explicitly disables purchases/push and is staging-only.

**Next:** extend the reviewed staging configuration with environment-specific validation, private storage and capability-key handling, then create/review the actual production adapter. Preserve staging/provider separation. **Accept with:** local configuration tests plus controlled staging portal sign-in, native Google, private upload/download and Contractor link round trips. This is confirmed source wiring, not a statement about today's deployed host or outage.

### 6. P2 — Late push registration can restore a departed account's binding

[NotificationManager:652](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/NotificationManager.swift:652) validates local generation after registration returns; [DeviceController.registerDevice:28](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Controllers/DeviceController.swift:28) deletes/reinserts token ownership without an installation/session revision. A delayed A request can commit after B's registration. Owner-scoped unregister and auth-gated registration are present; they do not order server writes. Logout server unregistration remains one-off.

**Next:** use a server-enforced current installation/session binding and durable departed-session cleanup. **Accept with:** force old registration to finish last across offline logout/account switching, then verify final ownership and real-device APNs delivery. Do not treat local task cancellation as server rollback.

## Current protections and verification gates

- **Identity/session controls present:** [JWTAuthMiddleware.authenticate](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Middleware/JWTAuthMiddleware.swift:32) checks active lifecycle, auth version and matching subject; direct legacy upload uses it. [BrowserSessionService](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Services/BrowserSessionService.swift:40) has hashed, revocable sessions, Secure/HttpOnly host cookies, environment/origin binding and mutation CSRF. `revokeAll` invalidates native versions too. Old claims that server sessions cannot be revoked are obsolete. Native logout does not invoke that server mechanism.
- **Google code boundary present:** [GoogleIdentityProof.swift](/Users/danielmccann/Desktop/Projects/SnagLinkBackend/Sources/App/Services/GoogleIdentityProof.swift:59) verifies signed token audience/presenter/nonce/time; one-use challenges and proven account linking avoid email-based merges. [NativeGoogleFlow](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/NativeGoogleFlow.swift:63) checks account generation; its ephemeral transport refuses redirects and proof retries. Native production Google configuration is deliberately unavailable in [NativeGoogleProvider:11](/Users/danielmccann/Desktop/Projects/Snaglist/SnagLink/Snaglist/Services/NativeGoogleProvider.swift:11). Real provider, cancellation, disconnect/recovery and release-client configuration acceptance remain separate. Do not claim production Google support from the staging implementation.
- **Portal transport present:** [client.ts:59](/Users/danielmccann/Documents/Codex/2026-09-06/her/SnaglistPortal/src/api/client.ts:59) uses same-origin cookies, no-store, no redirects and explicit CSRF; production code does not persist auth credentials in browser storage. [main.tsx](/Users/danielmccann/Documents/Codex/2026-09-06/her/SnaglistPortal/src/main.tsx) confines design fixtures to development. Deployment must prove same-origin routing, cookie/header forwarding, no caching of protected responses, and production fixture exclusion.
- **Release configuration:** app/Clip API hosts are HTTPS; no broad ATS exception was found in inspected plists/project settings. Main camera/photo/location/microphone/speech/Face ID purpose strings and Clip camera string exist. Tokens use `WhenUnlockedThisDeviceOnly` Keychain storage with separate staging service IDs. Staging has separate bundle/store and disables production purchases, pushes and app groups. Clip Release excludes DEBUG. These source checks do not validate an archive or device permission flow.
- **Limited secret scan:** no obvious private-key, cloud-access-key or server-secret literal candidate appeared in scanned tracked release source/config files. The RevenueCat public SDK key and OAuth client IDs are public configuration, not server secrets. This was not a git-history, environment-file or packaged-binary secret audit.
