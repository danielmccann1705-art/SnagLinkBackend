## Assessment and smallest complete slice

There is no existing normalised canonical drawing/version/page/annotation graph to expose. Current register coverage must continue to omit those entities. The useful next implementation is a complete initial-drawing journey: private source upload → bounded processing → stable drawing/version/page publication → revisioned snag pin → immutable bootstrap/delta → authorised manager and explicitly selected Contractor-link page reads → second native installation. Build one initial immutable version and a replacement guard; drawing comparison and automatic pin migration stay in the brief's future backlog.

Preserve the existing native concept that each selected sheet is an `SLDrawing` with its own UUID. For the initial implementation, a canonical `Drawing` represents one named sheet. A multi-page PDF is one private source asset from which the user selects several sheets; publication creates one Drawing/initial Version/Page per selected sheet. Those drawings may reference the same private source asset. This matches current native page selection without merging old drawing UUIDs or inventing a mandatory building/floor hierarchy. A PDF's source page number and the sheet's display order are distinct fields.

The slice is complete only when original bytes, page provenance/geometry, private renditions, pin relations and recovery semantics work together. Merely adding drawing IDs to an API response is insufficient.

## Identity and schema contract

Add migrations; never change shipped migrations or repurpose `synced_drawings`/`media_assets`. Use PostgreSQL composite scope FKs and the current workspace transaction lock. Every public client-created UUID is stable in the durable outbox; a foreign-scope collision fails without revealing its record. Timestamps attributed to a server actor are separate from unverified legacy source dates.

The `drawings.currentVersionId` relation must point to a version for that same drawing/project (deferrable constraint permits atomic initial publication). Each version-page row carries assetId and uses composite FKs `(assetPageId,assetId,projectId)` and `(versionId,drawingId,assetId,projectId)` so even two assets in the same project cannot be crossed. Pin targets use `(versionPageId,versionId,drawingId,projectId)`. All geometry, rendition and history references use same-project composite FKs; UUID uniqueness alone is insufficient. Assets may be reused by several sheet versions **inside the same project**. No cross-project deduplication or inherited entitlement is introduced.

For determinism, a ready asset's processor profile and page hashes are immutable. A renderer upgrade creates a new processing revision/asset instead of overwriting an existing page rendition; retry of the original profile either yields the recorded result or a clear processing conflict. Selected version-page UUIDs remain stable after a crash/retry.

Pending source bytes/pages are visible only to their uploader. A published drawing makes its selected pages project-readable. Publication must explicitly acknowledge that the full original source PDF, if retained as project source, is available to internal project readers even if only some sheets are displayed. The contractor never receives that whole source PDF through sheet selection. If internal full-source sharing is inappropriate, require a deliberately extracted source file before publication; do not silently treat selection as PDF redaction.

## Geometry and native mapping

Coordinate contract: `display_top_left_v1`, x right, y down, normalised [0,1] over the exact published, oriented sheet rectangle. Persist PDF mediaBox, cropBox, selected displayBox, `/Rotate`, userUnit, sourcePageIndex, rendered size and the source-to-display affine transform. Do not infer PDF rotation from a landscape thumbnail or automatically change a crop box after pins exist.

For new PDFs, choose the explicit effective crop box, with media box fallback only when the parser reports no crop box, and apply the document rotation. Preserve the parser's actual box and transform. The worker's canonical rendered page defines placement on native, portal, contractor and report. Native/web may use the page rendition directly; an alternative PDF renderer must pass the same coordinate fixtures before replacing that rendition.

The reference transform is documented through source rectangle and rotation. For unrotated PDF coordinates, u=(x-x0)/width and v=(y-y0)/height (PDF y up). Display normalised coordinates are (u,1-v) at 0°, (v,u) at 90° clockwise, (1-u,v) at 180°, and (1-v,1-u) at 270°. Include userUnit, nonzero box origins and the actual renderer transform in test fixtures; do not independently rely on SDK rotation conventions. Client image-fit, zoom and pan happen after this transform and never alter stored pin coordinates.

For existing native drawings, the current displayed JPEG is the authoritative legacy coordinate surface. Preserve its bytes/size/orientation and its SLDrawing UUID. Treat it as an initial one-page image version when original-PDF mapping is unproven. An available source PDF may be linked only through an explicit import/provenance record whose selected page and image relationship have been checked. The initial version still references the legacy raster asset and its geometry; the PDF is a separate verified source-provenance asset. Do not switch that version’s surface to a new PDF render. Otherwise preserve the PDF in the recoverable import archive and report the missing association. Never merge separate legacy SLDrawing UUIDs into one inferred PDF drawing. A preserved but unassociated source file remains an open full-recovery item.

`pageNumber` is the legacy human source page number, not necessarily canonical pageIndex+1: an imported PDF's page 7 may be this sheet version's pageIndex 0. Native adoption needs explicit canonical drawing/version/page IDs and source-page provenance, while keeping existing display name/order and local paths. Use the validated FloorPlans-first resolver with legacy Photos fallback only for a missing canonical file; reject traversal, symlink escape and invalid canonical paths, and do not fall back over a corrupt present file.

## Annotation boundary

Do not present PDF report editor state as a drawing-annotation graph. For current snag-photo parity, the next evidence slice must persist both original and annotated raster as distinct immutable files with a typed relation.
